# Git Version Control Workflow

## Project Overview

This project demonstrates Git and GitHub through collaborative development and conflict resolution.
It covers repository initialization, branching strategies, commits, pull requests, merging, tags, and project documentation.

## Objectives

- Understand Git version control.
- Create and manage multiple branches.
- Follow feature-based development.
- Use Pull Requests to merge code.
- Maintain meaningful commit history.
- Configure `.gitignore`.
- Create Git tags for version identification.
- Document Git commands and workflows.

## Tools Used

- Git
- GitHub
- Visual Studio Code
- Ubuntu (WSL)

## Branching Strategy

| Branch | Purpose |
|---|---|
| main | Stable project version |
| dev | Development and integration |
| feature/git-documentation | Feature development and documentation |

## Git Workflow

1. Initialize a local Git repository.
2. Create and configure project files.
3. Push the project to GitHub.
4. Create development and feature branches.
5. Make changes and commit them.
6. Push feature branches to GitHub.
7. Create Pull Requests.
8. Merge feature branches into dev.
9. Merge dev into main.
10. Create Git tags.

## Learning Outcomes

- Practical understanding of Git.
- Branch management and collaboration.
- Pull Request-based development.
- Version tracking using Git tags.
- Git conflict management.
